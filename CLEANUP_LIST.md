## 2. CONFLICT & OVERLAP AUDIT (ARCHITECTURAL REPAIR IN PHASE 1)

### A. Prototype Stylesheet & Script Overlaps in `layout/theme.liquid`
Currently, `layout/theme.liquid` loads three legacy prototype assets after Minimog's primary compiled stylesheet (`main.css`):
1. **`assets/theme.css` (45.6 KB):**
   * *Conflict:* Injects an aggressive global reset: `* { box-sizing: border-box; margin: 0; padding: 0; }` that disrupts Minimog component spacing, paddings, and button alignments.
   * *Dead Selectors:* Contains dozens of CSS selectors targeting DOM elements that only existed in earlier prototypes (`#aura-preview-root`, `#aura-custom-header`, `.aura-hero-grid`, `.aura-mock-nav`).
   * *Plan for Phase 1:* Remove `{{ 'theme.css' | asset_url | stylesheet_tag }}` from `layout/theme.liquid`. Extract legitimate custom utility classes and tokens into a scoped `assets/aura-base.css` without global resets or `!important` declarations.
2. **`assets/theme.js` (34.7 KB):**
   * *Conflict:* Binds prototype click handlers, mock cart routes, and an inline preview router that directly conflicts with native Minimog custom elements (`<m-cart-drawer>`, `<variant-picker>`, `<m-product-form>`).
   * *Plan for Phase 1:* Remove `theme.js` script tag from `layout/theme.liquid`. Keep native Web Components fully authoritative.
3. **`assets/custom.css` (12 bytes):**
   * *Conflict:* Stub file originally added to silence a stylesheet link in `style-tags.liquid`.
   * *Plan for Phase 1:* Unify custom styling into `assets/aura-base.css` and eliminate redundant asset calls.
